## Мета роботи

Реалізувати та навчити автоенкодери для відновлення, стиснення або очищення даних від шуму, а також дослідити можливості виявлення аномалій і представлення даних у латентному просторі.

Обов'язково порівняти **щонайменше 2 різні архітектури автоенкодерів**, наприклад:

- Fully Connected Autoencoder (FC-AE / MLP-AE);
- Convolutional Autoencoder (ConvAE);
- Denoising Autoencoder (DAE);
- Sparse Autoencoder;
- Variational Autoencoder (VAE);
- Residual Autoencoder.

Оцінити якість реконструкції, вплив розмірності латентного простору, складності архітектури та параметрів навчання.

## Що здати

- **Ноутбук/репозиторій з кодом:** читабельні секції (дані → preprocessing → архітектура → навчання → оцінка → візуалізації → висновки).
- **Збережені моделі:** найкращі ваги щонайменше двох автоенкодерів та демонстрація інференсу на 10 або більше зразках із тестової вибірки.
- **Короткий звіт (1–2 стор.):** опис архітектур, графіки навчання, таблиця метрик, візуалізації результатів та висновки.
- **Візуалізації реконструкції:** для зображень показати оригінал, реконструкцію та карту похибки. Для denoising-задач додатково показати зашумлений вхід.
- **Аналіз латентного простору:** дослідити представлення, які формує енкодер, за допомогою PCA, t-SNE або UMAP (для 2D-візуалізації), або шляхом зміни/інтерполяції латентних векторів.
- **Таблиця порівняння моделей:** кількість параметрів, розмірність латентного простору, метрики якості реконструкції, час навчання та швидкість інференсу.

## Мінімальні вимоги

1. Реалізувати та навчити щонайменше **2 архітектури автоенкодерів** відповідно до свого варіанта.
2. Навчати моделі не менше **10 епох** (або застосувати Early Stopping із контролем validation loss).
3. Розділити дані на train / validation / test. Не використовувати test для вибору гіперпараметрів, порогів аномалій або найкращої моделі.
4. Використати відповідну функцію втрат, наприклад MSE або MAE. Для VAE додатково врахувати KL-divergence.
5. Оцінити якість на відкладеній тестовій вибірці:
   - для реконструкції зображень: MSE, MAE, PSNR, SSIM;
   - для часових рядів або ознакових векторів: MSE, MAE;
   - для виявлення аномалій: ROC-AUC, PR-AUC та F1-score (за наявності міток).
6. Побудувати графіки train loss та validation loss.
7. Візуалізувати щонайменше 10 прикладів роботи моделей. Для зображень додати порівняння оригіналу і реконструкції; для сигналів — відповідні графіки.
8. Дослідити вплив розмірності латентного простору (наприклад, 16, 32, 64), використавши хоча б дві різні розмірності для однієї з моделей.
9. Зафіксувати random seed, гіперпараметри, розміри вибірок та версії основних бібліотек.

> **Важливо:** якщо завдання передбачає видалення шуму, модель отримує на вхід зашумлені дані, але повинна відновлювати їхню чисту версію. Якщо завдання передбачає виявлення аномалій, навчання автоенкодера проводиться на нормальних даних (якщо інше не визначено варіантом).

## Обов'язкове порівняння архітектур (лаба 3)

### 1. Вибір моделей

Порівняйте мінімум 2 моделі. Приклади допустимих пар:

- FC-AE vs Convolutional AE;
- Convolutional AE vs Denoising AE;
- Standard AE vs Sparse AE;
- Convolutional AE vs Variational AE;
- Basic ConvAE vs Residual ConvAE.

Можна використати інші архітектури за погодженням із викладачем.

### 2. Справедливі умови експерименту

- Використовувати однаковий train/validation/test split.
- Використовувати однаковий розмір вхідних даних та нормалізацію.
- Для основного порівняння за можливості зафіксувати однакову розмірність латентного простору.
- Використовувати порівнянний бюджет навчання (епохи, оптимізатор, batch size).
- Оцінювати обидві моделі на тих самих тестових прикладах.

Для DAE необхідно оцінювати обидві моделі на однаково зашумлених тестових даних. Для VAE порівнювати якість реконструкції окремо від загальної функції втрат, що містить KL-компонент.

### 3. Що порівнювати

- Кількість параметрів (млн);
- Розмірність латентного простору (latent dimension);
- Якість реконструкції: MSE / MAE / PSNR / SSIM;
- Час навчання однієї епохи;
- Latency інференсу на CPU та/або GPU;
- Візуальну якість реконструкції;
- Структуру латентного простору.

Для задач anomaly detection додатково порівняти ROC-AUC, PR-AUC, F1-score та приклади False Positive / False Negative.

### 5. Обов'язкові візуалізації

**Реконструкція.** Для кожної архітектури побудувати візуалізації:

- Reconstructed image / signal;

- Noisy input (для DAE).

**Латентний простір.** Використати PCA, t-SNE або UMAP для візуалізації представлень енкодера. Якщо датасет має мітки класів, дозволяється використати їх для кольорового позначення точок (але не для навчання автоенкодера).

**Аналіз помилок.** Відібрати 5 найкращих і 5 найгірших реконструкцій, пояснити можливі причини похибок.

### 1. MNIST — Стиснення зображень цифр

**Завдання:** реалізувати Fully Connected AE та Convolutional AE. Порівняти якість реконструкції рукописних цифр при latent dimension = 16, 32, 64. Дослідити компроміс між якістю реконструкції та ступенем стиснення.

Датасет: <https://pytorch.org/vision/stable/generated/torchvision.datasets.MNIST.html>

### 2. Fashion-MNIST — Видалення шуму (Denoising)

**Завдання:** реалізувати звичайний ConvAE та Denoising AE. Додати Gaussian noise і salt-and-pepper noise. Порівняти відновлення зображень за трьох рівнів шуму, використовуючи MSE, PSNR та SSIM.

Датасет: <https://github.com/zalandoresearch/fashion-mnist>

### 3. CIFAR-10 — Реконструкція кольорових зображень

**Завдання:** реалізувати стандартний ConvAE та Residual ConvAE. Порівняти якість відновлення RGB-зображень, кількість параметрів та швидкість інференсу. Проаналізувати, які класи зображень реконструюються найгірше (мітки класів використовувати лише для аналізу).

Датасет: <https://www.cs.toronto.edu/~kriz/cifar.html>

### 4. CIFAR-100 — Варіаційні автоенкодери

**Завдання:** порівняти Convolutional AE та Variational Autoencoder (VAE). Дослідити вплив KL-divergence на структуру латентного простору та якість реконструкції. Виконати інтерполяцію між латентними представленнями двох зображень.

Датасет: <https://www.cs.toronto.edu/~kriz/cifar.html>

### 5. SVHN — Стійкість автоенкодерів до спотворень

## Додаткові вимоги для окремих типів задач

**Для Denoising Autoencoder:**

- Продемонструвати три рівні шуму.
- Показати Input (noisy) → Output (reconstructed) → Target (clean).
- Порівняти з автоенкодером, що навчався без шуму.

**Для Variational Autoencoder:**

- Реалізувати reparameterization trick.
- Показати reconstruction loss та KL-divergence окремо.
- Виконати інтерполяцію в латентному просторі.
- Продемонструвати генерацію нових зразків.

**Для Anomaly Detection:**

- Не використовувати аномальні тестові приклади під час навчання.
- Визначити поріг anomaly score за validation set, а не за test set.
- Якщо у validation set є лише нормальні приклади, можна використати фіксований квантиль їхньої похибки реконструкції.
- Показати приклади правильних та помилкових прогнозів.
